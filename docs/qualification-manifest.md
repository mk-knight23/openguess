# Playable qualification manifest boundary

`npm run build` runs `npm run validate:playable` before TypeScript and Vite. Every source pack claiming a newly qualified profile must have valid replay receipts and a SHA-256 digest matching its actual final default playable subjects and questions. The check uses Node's native crypto implementation. The browser projection remains synchronous and trusts this checked manifest; it does not hash packs during play. Direct Vite builds and edited development packs bypass the release boundary and must not be used to publish a qualified-catalog claim.

The canonical payload is `{subjects, questions}`. Sort both arrays by ID using Unicode code-point order. For every subject retain all JSON fields except the derived `qualification` object; retain every question field. Recursively sort object keys by Unicode code point, preserve other array orders, and serialize compact JSON with Unicode characters unescaped and UTF-8 encoding. Numbers must be safe integers; floating point and unsafe integer metadata fails closed. `scripts/knowledge/qualify.py` implements the same producer contract, and a cross-language test checks parity.

Mint replay receipts only after transforming source records into the final runtime shape. Hash the exact qualified-plus-legacy playable union and familiar question set used for that replay. A quarantine-pilot digest cannot qualify a differently transformed runtime pack. Changing a playable subject, its evidence, a rival, or question metadata requires a fresh final-universe replay and receipt. Adding a quarantined record does not change the playable universe. Duplicate subject IDs fail validation whenever qualification is claimed.

Legacy featured profiles remain explicitly exempt from new qualification certification. No current profile has been newly qualified; this gate does not claim completion of the catalog target or independently verify the truth of supplied evidence or replay results.
