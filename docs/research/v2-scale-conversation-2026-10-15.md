Date: 2026-10-15. Baseline: `5df3b5712cb3a2cd5ad90fc81e2b136e0591fbd4` (published 0.2.1). This is research, not an implementation or a claim of reference parity.

## Findings that change the upgrade

The requested target is **5,000 playable subjects in each of five categories**, confirmed by the user after the total-versus-per-category question. That means at least 25,000 playable subjects. The existing total of 5,584 records is neither that target nor evidence of comparable play quality.

Known means explicit Boolean true or false; missing/null facts were not counted. These are stored-data measurements, not a new gameplay evaluation. All nonfeatured profiles lack the familiar signature tier required by the current readiness rule. Increasing importer limits would not fix that.

`scripts/import-wikidata.py` imports positive structured claims from one provider. Its seed limits are approximately 1,100–1,200 per category. Animal selection is primarily mammals; object selection is tools, vehicles and instruments. Absent facts correctly remain unknown. The upgrade needs broader scope, much denser semantic evidence and supported negative distinctions, without converting absent statements into false.

## What the current engine actually does

`src/App.tsx` appends the answer immediately. `src/useInference.ts` sends the whole current history to a worker or the validated synchronous fallback. `src/engine.ts` reranks candidates from that history before selecting the next question. It is already answer-conditioned; it does not pre-generate an unrelated random list.

The observed product complaint still has concrete causes. Selection applies a 10% score penalty to the previous question family, favoring topic changes in close decisions. Questions have prerequisites, equivalence groups and correlated-evidence groups, but no explicit follow-up purpose, topic thread or answer-conditioned dialogue policy. Equivalence suppression depends on manually complete labels. The 5% seeded tie band can pick different useful questions, but it does not supply conversational continuity. No minimum reading/thinking interval exists: the next question appears as soon as inference completes.

The proposed remedy is separate conversation context and inference state. Update evidence first, choose the next useful question from that updated state, favor a relevant nonredundant follow-up, and publish it after a short cancellable thinking interval. Retain recovery paths when a prerequisite answer is mistaken. A rigid tree that permanently excludes a subject after one wrong answer would regress the last release.

## Research and source implementations

- [Sasson and Kenett, 2023](https://doi.org/10.3390/bdcc7010026), [publisher PDF](https://mdpi-res.com/d_attachment/BDCC/BDCC-07-00026/article_deploy/BDCC-07-00026.pdf?version=1674979399): their 2021–22 experiments collected 7,473 distinct character questions and found reworded repetitions, shifting opening distributions and broad questions after specific ones. Constant-answer API experiments are not human accuracy tests or today's web policy. Topic clusters do not establish consecutive-turn coherence. Their proposed algorithmic/gamification explanations remain hypotheses. Thus strict nonrepetition and coherent follow-ups are our requested improvements, not universal properties already proven of Akinator.
- [De Bruyn et al., 2022](https://aclanthology.org/2022.blackboxnlp-1.7/): an Akinator-derived object-question study supports combining reusable broad properties with subject-specific knowledge. Its filtered collection is not an unbiased accuracy sample. This was already part of the prior investigation.
- [Bertolazzi et al., 2023](https://aclanthology.org/2023.inlg-main.11.pdf): the paper separates informative questions, explicit updates to the hypothesis space and appropriate stopping. Its small hierarchical spaces and historical ChatGPT experiment are not an evaluation of current models or Limule. It motivates keeping the candidate state explicit rather than asking a language model to improvise an entire game.
- [Nowak's generalized binary search analysis](https://arxiv.org/abs/0910.4397): adaptive query quality depends on how questions partition plausible hypotheses under stated assumptions. Coherence must be constrained by information value rather than replacing it.
- [Aaklon/akinator](https://github.com/Aaklon/akinator/blob/main/akinator/engine.go): inspected actual Go source for posterior-based information gain, scope eligibility, soft thresholds and exploration. The code requires a scope question to have a sufficiently positive answer before a scoped child is eligible. This is useful prior art, not the official server. Its fixed 20-question cap and exploration bonus should not be copied without evaluating our own data.
- [Isaka-code/llm-20-questions](https://github.com/Isaka-code/llm-20-questions/blob/main/src/keyword_question_mapping.py): inspected actual question-matrix code that removes asked questions and evaluates candidate reduction. Its separate [dictionary strategy](https://github.com/Isaka-code/llm-20-questions/blob/main/src/dictionary_binary_search.py) includes alphabetical ordering queries. Those are inappropriate for our semantic game despite the competition result.
- [open20q](https://github.com/Anaphory/open20q): its author explicitly flags dense subject-by-question storage as a scaling concern and discusses dependent features. This favors sparse facts and compact indexes; it does not justify claiming an unmeasured latency or importing its code without an appropriate license.

Repository source files were read through the GitHub API without installing or executing them. No third-party engine code was copied.

## Proposed evidence bar

Measure imported records, canonical distinct subjects, semantically qualified profiles and successfully replayed profiles separately. Count a subject toward the requested target only after identity/provenance checks, familiar clue coverage and end-to-end recovery tests pass. Independently audit a category-stratified sample because an oracle derived from the same mistaken truth table can still report a perfect score.

Require no same-ID or equivalent-proposition repetition within a round. Treat implication as scoped: only definite supported evidence establishes hard closure, while probable/posterior support remains soft context. Derived implications retain the original evidence group and do not add confirmations. Do not suppress every related clue: a franchise follow-up can be both connected and informative. Evaluate semantic repetition, unsupported premises, useful follow-ups and recovery on deliberately constructed counterexamples as well as full-catalog replay.

Independent review found that the existing evaluator applies `featuredPack` and then filters `featured` again. The new default game, daily targets, displayed counts and evaluator must use the same full qualified projection. Replay against the complete final category, not isolated batches; retain separate old-cohort regression and expanded-catalog results. Add held-out seeds, withheld confirming clues, near-rival distinctions and indistinguishable-cluster reporting. A numeric fact-count screen is not proof of independent knowledge.

The presentation controller must invalidate pending reveals on history correction, Give up, navigation and pack/settings changes as well as the obvious restart/undo paths. Publish question, guess, exhaustion and mood consistently; lock answer acceptance synchronously before a React render can admit a second event.

The 2–3 second interval is the user's product choice. Browser scheduling and inference can exceed three seconds on a slow/backgrounded device, so the safety rule is never to reveal an uncomputed or stale question merely to meet a stopwatch ceiling.
