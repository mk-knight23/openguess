# OpenGuess v1 — 2026-10-14

## Goal

Build an original, free, open-source browser guessing game, informed by REA investigation of Akinator's public website and publisher documentation. The reference game is not a dependency. Its code, artwork, branding, private algorithm and database are not copied.

## Research boundary

REA browser discovery, passive page inspection, screenshot and static bundle inspection reached a Cloudflare challenge. Live gameplay and game endpoints are unobserved. Publisher material describes adaptive character guessing and community contributions; it does not disclose the private Limule implementation. Bayesian updates and information-gain question selection are our design.

## Architecture

React + TypeScript + Vite static application. A pure inference engine accepts a versioned local catalog, history and rejected candidates. Five answers update normalized candidate weights. Unknown answers provide no evidence. Select unasked questions by expected entropy reduction. Undo reconstructs from history; rejection removes a candidate without inventing evidence. The app has no remote AI calls or backend, making each player's device do the inference.

## V1 product contract

- Responsive, accessible original observatory-themed interface named OpenGuess.
- Character/people catalog authored independently with explicit traits, attribution policy and documented limitations; show supported catalog before play.
- Five choices: yes, probably, don't know, probably not, no. Keyboard support, undo, restart, result confirmation and rejection.
- Inference explanation and candidate transparency as opt-in, to avoid spoiling play.
- Honest exhausted/unknown states rather than certainty when answers cannot distinguish entries.
- Local-only preferences and stats; export a contribution proposal rather than pretend to update a shared database.
- No pricing, ads, subscriptions, account requirement or paid service dependencies.

## Tasks and verification

1. `package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`: minimal toolchain; lock dependencies and verify install/build.
2. `src/data/catalog.ts`, `src/types.ts`, dataset tests: independent starter catalog, valid IDs/traits and unique distinguishable signatures.
3. `src/engine.ts`, engine tests: test normalized updates, unknown answers, uncertain answers, information gain, undo/rejection and complete-catalog replay before implementing each behavior.
4. `src/App.tsx`, `src/styles.css`, UI tests: start, questions, answers, catalog, result, contribution, local stats and accessible navigation. Original SVG identity, no reference assets.
5. `docs/research/akinator.md`, architecture/scaling/roadmap/security/contribution documentation, README, MIT license, CI.
6. Run unit/integration tests, strict typecheck, production build, dependency audit, independent spec and quality/security reviews. Real desktop/mobile browser QA and REA capture of the built app.
7. Publish a clean public GitHub repository under the authenticated account, tag v0.1.0. Attach review PR if one is created. Record findings and limitations.

## Scaling and future versions

V1 is distributed static assets plus client inference; no central gameplay server. Network costs are hosting/CDN costs rather than per-question AI costs. Free software is not a guarantee of unlimited free hosting. Larger data packs can be lazy loaded and scored in a worker. Shared learning is a separate future opt-in service with moderation, provenance, validation, rate limits and privacy controls. Animals/objects/movies, multilingual packs, daily challenges and benchmarks belong to later versions.
