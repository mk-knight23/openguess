# Scaling

Static assets and lazy-loaded packs can be distributed through a CDN; every player's browser performs inference. More visitors increase transfer and hosting costs without creating a central per-question AI workload. Free software and free service tiers do not promise unlimited free operation.

With C entities and Q questions, straightforward selection remains O(C × Q). V2 groups probability masses per question to reduce allocation and uses a worker to preserve interface responsiveness. Pack size, sparse facts, name fallback questions and worker serialization all affect cost. Desktop timings do not establish lower-end mobile performance; consult [benchmarks](benchmarks.md) and measure real target browsers before expanding coverage.

Cache hashed assets, refresh HTML and version packs with compatible engine schemas. Lazy loading avoids downloading all themes at startup. Future column-oriented traits, compressed packs or indexes require measured gains and compatibility tests.

Optional cloud accounts and backups add service quotas, storage, authentication traffic and abuse exposure. Public rankings need moderation and server validation if treated competitively; client-reported wins are presently personal/social signals. Maintain local-only play when cloud quotas are reached. Shared catalog learning remains a separate future service requiring provenance, moderation, validation, privacy and rate limits.
